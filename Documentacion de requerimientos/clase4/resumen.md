# Documentación de Requerimientos

## ¿Por qué documentar?

La documentación permite conservar la información del proyecto, facilitar la comunicación entre cliente y equipo de desarrollo, servir como evidencia legal y apoyar las pruebas del sistema.

### Funciones principales

- Acuerdo entre cliente y equipo.
- Guía para desarrolladores.
- Verificación mediante pruebas.
- Conservación del conocimiento.
- Evidencia para auditorías.

## IEEE 830

Es un estándar internacional que define cómo elaborar un documento SRS (Software Requirements Specification).

### Beneficios

- Estructura organizada.
- Facilita la comunicación.
- Mejora la calidad de los requerimientos.
- Permite auditorías y trazabilidad.

## Estructura del SRS

1. Introducción.
2. Descripción General.
3. Requisitos Específicos.
4. Apéndices.

## Características de un buen SRS

- Correcto.
- No ambiguo.
- Completo.
- Consistente.
- Verificable.
- Modificable.
- Trazable.
